# Token Optimization Notes

Practices used throughout this pipeline to keep context windows small and avoid redundant MCP calls:

- **Stage isolation**: each pipeline stage is a separate subagent (`.github/agents/*.agent.md`) with a
  minimal `tools` list, so irrelevant tool output never enters another stage's context.
- **Response caching**: raw MCP responses (Jira issue payloads, PR metadata) are cached under `.cache/`
  per `jiraId` so repeated runs/retries don't re-fetch unchanged data. See
  [.cache/prompt-cache.md](.cache/prompt-cache.md).
- **Doc handoff, not transcript handoff**: stages pass context via the markdown files in `docs/<jiraId>/`
  instead of replaying full chat transcripts between agents.
- **Templates over regeneration**: `docs/_template/` defines the exact shape of every doc so agents fill in
  sections rather than re-deriving structure each run.
- **Narrow MCP tool grants**: each agent only gets the MCP server it needs (e.g. only `07-verification`
  and `08-pr-creator` get `github/*`; only `01-requirements` gets `jira/*`).
